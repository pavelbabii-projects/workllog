# Worklog — учет рабочего времени

Небольшое веб-приложение для учета рабочего времени сотрудников. Интерфейс на русском языке, данные сохраняются в SQLite. В проекте используются только вымышленные тестовые данные.

## Возможности

- Добавление сотрудников; имя не может быть пустым, повторяющиеся имена отклоняются.
- Запуск таймера с обязательным описанием задачи и остановка таймера.
- Не более одного активного таймера на сотрудника. Ограничение дополнительно защищено уникальным частичным индексом SQLite.
- Отчеты за период: журнал записей, суммарное время, группировка по сотрудникам и фильтр по сотруднику.
- Активные таймеры и записи переживают перезапуск сервера, поскольку хранятся в SQLite.
- Адаптивный интерфейс и понятные состояния для пустых списков и отчетов.

## Требования

- Node.js 24 (используется встроенный модуль `node:sqlite`)
- npm

## Запуск локально

```bash
npm install
npm start
```

Откройте <http://localhost:3000>. По умолчанию база создается в `data/work-time.sqlite`; папка и база создаются автоматически. Для другого пути можно задать `DB_PATH=/absolute/path/to/file.sqlite`. Порт задается через `PORT`, например `PORT=8080 npm start`.

Режим разработки с перезапуском сервера при изменениях:

```bash
npm run dev
```

## Проверки

```bash
npm test
```

Тесты используют отдельную временную базу и проверяют:

1. отклонение пустого имени и дубликата сотрудника;
2. отклонение запуска без описания задачи;
3. повторный запуск таймера для того же сотрудника (ожидается HTTP 409);
4. остановку таймера и запрет повторной остановки;
5. пустой отчет (пустые массивы и нулевая сумма);
6. сохранность сотрудника и записи после открытия файла SQLite отдельным соединением.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/employees` | Список сотрудников |
| `POST` | `/api/employees` | Создать сотрудника: `{ "name": "Анна Смирнова" }` |
| `GET` | `/api/timer/active` | Активные таймеры |
| `POST` | `/api/timer/start` | Запуск: `{ "employeeId": 1, "task": "Подготовить отчет" }` |
| `POST` | `/api/timer/:id/stop` | Остановка таймера |
| `GET` | `/api/report?from=2026-01-01&to=2026-01-31&employeeId=all` | Отчет за период |
| `GET` | `/api/health` | Проверка доступности сервера |

Период отчета передается в формате `YYYY-MM-DD`. Границы периода в API трактуются как UTC. Записи включаются в отчет по дате начала; активные записи учитываются по текущей длительности на момент формирования отчета.

## Ошибки и граничные случаи, которые важно проверить

В ходе финальной проверки убедитесь, что описанные ниже случаи действительно воспроизводились и были исправлены; оставьте в этом разделе только фактически обнаруженные ошибки:

- **Повторный запуск таймера:** проверка только на клиенте ненадежна, потому что запрос можно отправить напрямую или почти одновременно. Защита реализована на сервере и дополнена уникальным частичным индексом SQLite.
- **Пустые значения:** имя сотрудника и описание задачи проверяются после `trim()` на сервере, а не только атрибутом `required` в HTML.
- **Вставка пользовательского текста в HTML:** имена и описания экранируются перед добавлением в DOM, чтобы введенный текст не интерпретировался как разметка.
- **Пустой отчет:** отсутствие строк должно отображаться как штатное состояние, с нулевой суммой, а не как ошибка.
- **Повторная остановка:** сервер не должен повторно изменять уже завершенную запись.
- **Сохранение данных:** SQLite-файл находится вне статических файлов и не пересоздается при обычном перезапуске приложения.

## Ограничения и возможные улучшения

- Нет авторизации и разграничения прав — это соответствует условиям задания.
- Для простоты отчет группирует записи по дате старта; длительная задача, пересекающая полночь, целиком относится к дате начала.
- Для продакшен-развертывания следует добавить миграции БД, логирование, резервное копирование и конфигурацию часового пояса.


### Почему используется `node:sqlite`

В проекте используется встроенный модуль SQLite из Node.js 24, поэтому не требуется устанавливать `better-sqlite3`, Visual Studio Build Tools или компилятор C++. Это устраняет проблему сборки `MSB8020` на Windows. При запуске Node.js может показать предупреждение об экспериментальном статусе `node:sqlite` — для Node.js 24 это ожидаемо.
